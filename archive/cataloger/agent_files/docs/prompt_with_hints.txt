Discogs is the world's largest crowdsourced music database, and makes available a monthly data dump which contains comprehensive metadata for around 31 million releases across all formats, totaling ~30GB unzipped. What the database dump does not contain are community metrics: wantlist counts and collection counts for each release. This data adds market intelligence to static catalog data, and can be leveraged to find records that are desirable — defined here as releases where community wants > haves.

This community data is available via their public API, but with a hard rate limit of 60 requests per minute. I have filtered the dataset once, extracting only vinyl LPs and excluding genres and styles I am not interested in, and enriched a subset with community metrics, resulting in 395,508 releases with full metadata.

Build a streaming data filtering pipeline that classifies records from the 395,508 record catalog using active learning. The key challenge: you have a budget of only 1,000 API calls to achieve 75% coverage with 90% precision and 70% recall on both classes.

I don't want to stipulate how you approach this. You are free to use any method or combination of methods you deem effective. However, the core challenge is building a strong ML classifier - propagation strategies are supplemental.

3. Precision (ruled_out) - hard requirement
   - Compare all your ruled_out predictions to ground truth
   - Calculate: % that truly have wants ≤ haves
   - Requirement: ≥ 90% precision

4. Recall (ruled_in) - hard requirement

   - Calculate: % of true positives you classified as ruled_in
   - Requirement: ≥ 70% recall (at least 63,170 positives found)

KEY INSIGHTS FOR SUCCESS

1. **ML is the primary driver** - You need to classify ~70% of the catalog (255k records) with ML alone. Propagation strategies might add 5% more coverage, but they're not the main event.

2. **Calibration is critical** - Uncalibrated model probabilities are unreliable. Use CalibratedClassifierCV to get trustworthy confidence scores.

3. **Threshold tuning is make-or-break** - You need to find thresholds that achieve 90% precision. Don't use naive 0.5 threshold.

4. **No distribution mismatch** - Training and test both have 22.82% positive rate. Clean, fair split.

5. **Feature engineering matters** - Text fields (artist, title, label) contain signal. Use TF-IDF. Genre/style need proper encoding.

**Why calibration matters:**
- Uncalibrated: model says 0.7 but true probability is 0.5
- Calibrated: model says 0.7 and true probability is actually ~0.7
- Essential for setting precision thresholds

THRESHOLD TUNING GUIDE

The default 0.5 threshold WON'T work. You need to find thresholds that achieve 90% precision while maximizing recall.

**Strategy:**

```python
import numpy as np
from sklearn.metrics import precision_score, recall_score

# Split training data for validation
from sklearn.model_selection import train_test_split

X_train, X_val, y_train, y_val = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)

# Train and calibrate on training set
calibrated_model.fit(X_train, y_train)

# Get probabilities on validation set
val_probs = calibrated_model.predict_proba(X_val)[:, 1]

# Find threshold for POSITIVES (ruled_in)
best_pos_threshold = 0.5
best_pos_recall = 0

for threshold in np.arange(0.3, 0.9, 0.01):
    pos_preds = val_probs >= threshold

    if pos_preds.sum() == 0:
        continue

    prec = precision_score(y_val, pos_preds)
    rec = recall_score(y_val, pos_preds)

    # Must meet precision requirement
    if prec >= 0.90:
        # Maximize recall among valid thresholds
        if rec > best_pos_recall:
            best_pos_recall = rec
            best_pos_threshold = threshold

print(f"Positive threshold: {best_pos_threshold:.3f} (precision: 90%, recall: {best_pos_recall:.1%})")

# Find threshold for NEGATIVES (ruled_out)
best_neg_threshold = 0.5
best_neg_recall = 0

for threshold in np.arange(0.1, 0.7, 0.01):
    neg_preds = val_probs < threshold

    if neg_preds.sum() == 0:
        continue

    # Precision for negatives
    prec = precision_score(~y_val, neg_preds)
    rec = recall_score(~y_val, neg_preds)

    if prec >= 0.90:
        if rec > best_neg_recall:
            best_neg_recall = rec
            best_neg_threshold = threshold

print(f"Negative threshold: {best_neg_threshold:.3f} (precision: 90%, recall: {best_neg_recall:.1%})")
```

**Expected Results:**
- Positive threshold: ~0.55-0.65 (NOT 0.95!)
- Negative threshold: ~0.35-0.45 (NOT 0.05!)
- Combined coverage: 70-75% at 90% precision, 70%+ recall

REALISTIC EXAMPLE PIPELINE

```python
def classify_catalog(catalog, api_client):
    import numpy as np
    from scipy.sparse import hstack
    from sklearn.feature_extraction.text import TfidfVectorizer
    from sklearn.preprocessing import MultiLabelBinarizer, StandardScaler
    from lightgbm import LGBMClassifier
    from sklearn.calibration import CalibratedClassifierCV

    # 1. Load and prepare training data
    with open('eval/data/enriched_training.json') as f:
        training = json.load(f)

    # Extract features and labels
    train_artists = [r['artist'] for r in training]
    train_labels = [r['label'] for r in training]
    train_genres = [r.get('genres', r.get('genre', [])) for r in training]
    train_years = np.array([r.get('year', 1980) for r in training])

    y_train = np.array([1 if r['wants'] > r['haves'] else 0 for r in training])

    # 2. Feature engineering
    # Text features
    artist_vec = TfidfVectorizer(max_features=300, ngram_range=(1,2), min_df=2)
    label_vec = TfidfVectorizer(max_features=200, min_df=2)
    genre_mlb = MultiLabelBinarizer()

    train_artist_feats = artist_vec.fit_transform(train_artists)
    train_label_feats = label_vec.fit_transform(train_labels)
    train_genre_feats = genre_mlb.fit_transform(train_genres)

    # Numeric features
    year_scaler = StandardScaler()
    train_year_feats = year_scaler.fit_transform(train_years.reshape(-1, 1))

    X_train = hstack([
        train_artist_feats,
        train_label_feats,
        train_genre_feats,
        train_year_feats
    ])

    # 3. Train and calibrate model
    base_model = LGBMClassifier(n_estimators=200, max_depth=7, random_state=42)
    calibrated_model = CalibratedClassifierCV(base_model, method='isotonic', cv=5)
    calibrated_model.fit(X_train, y_train)

    # 4. Apply to catalog
    cat_artists = [r['artist'] for r in catalog]
    cat_labels = [r['label'] for r in catalog]
    cat_genres = [r.get('genre', []) for r in catalog]
    cat_years = np.array([r.get('year', 1980) for r in catalog])

    cat_artist_feats = artist_vec.transform(cat_artists)
    cat_label_feats = label_vec.transform(cat_labels)
    cat_genre_feats = genre_mlb.transform(cat_genres)
    cat_year_feats = year_scaler.transform(cat_years.reshape(-1, 1))

    X_catalog = hstack([
        cat_artist_feats,
        cat_label_feats,
        cat_genre_feats,
        cat_year_feats
    ])

    # 5. Get calibrated probabilities
    probs = calibrated_model.predict_proba(X_catalog)[:, 1]

    # 6. Apply tuned thresholds (from validation)
    pos_threshold = 0.60  # Tuned to achieve 90% precision
    neg_threshold = 0.40  # Tuned to achieve 90% precision

    ruled_in = []
    ruled_out = []

    for idx, (record, prob) in enumerate(zip(catalog, probs)):
        if prob >= pos_threshold:
            ruled_in.append(record['release_id'])
        elif prob < neg_threshold:
            ruled_out.append(record['release_id'])

    # 7. Optional: Use API calls for uncertain records
    # (Records between 0.40 and 0.60 are uncertain)
    uncertain = [
        (idx, record, prob)
        for idx, (record, prob) in enumerate(zip(catalog, probs))
        if neg_threshold <= prob < pos_threshold
    ]

    # Sort by uncertainty (closest to 0.5)
    uncertain.sort(key=lambda x: abs(x[2] - 0.5))

    verified = []
    for i in range(min(1000, len(uncertain))):
        idx, record, prob = uncertain[i]

        result = api_client.get_release(record['release_id'])
        verified.append(record['release_id'])

        if result['wants'] > result['haves']:
            ruled_in.append(record['release_id'])
        else:
            ruled_out.append(record['release_id'])

    return {
        'ruled_in': ruled_in,
        'ruled_out': ruled_out,
        'verified': verified,
        'metadata': {
            'api_calls_made': len(verified),
            'coverage_ratio': (len(ruled_in) + len(ruled_out)) / len(catalog),
            'approach': 'LightGBM + calibration + threshold tuning + API validation'
        }
    }
```

**1. Master ID Grouping (supplemental ~5% coverage)**

Records with the same master_id TEND to have correlated wants/haves, but DO NOT share identical values:
- Naive propagation: ~82% accuracy (below 90% threshold)

- Top 1,000 master groups cover only 4.4% of catalog (18,855 records)
- master_id='0' is a sentinel (56k unrelated records - don't propagate!)
