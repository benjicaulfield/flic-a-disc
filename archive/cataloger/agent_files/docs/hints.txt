HINTS FOR DISCOGS RECORD CLASSIFICATION

1. THRESHOLD TUNING

Don't use the default 0.5 threshold. With a 90% precision requirement and class imbalance (22.82% positive), you need to find thresholds that maximize recall while maintaining precision. Use a validation set to grid search thresholds - try ranges like 0.3-0.8 for positives and 0.2-0.7 for negatives. You can also use separate thresholds for each class (asymmetric classification). Records between thresholds can remain unclassified if neither threshold is met.

2. MODEL CALIBRATION

Tree-based models (RandomForest, LightGBM, XGBoost) produce uncalibrated probabilities. Apply CalibratedClassifierCV with isotonic or sigmoid method before using probabilities for decisions. Without calibration, a model claiming 80% confidence might only be 60% accurate. Calibration ensures that among predictions with probability p, approximately p% are actually positive.

3. FEATURE ENGINEERING FOR TEXT AND MULTI-LABEL DATA

- Text fields (artist, title, label): Use TF-IDF with n-gram ranges (1,2) and min_df=2 to filter rare terms. Limit max_features (200-500) to control dimensionality.
- Multi-label fields (genres, styles): Use MultiLabelBinarizer, not one-hot encoding.
- Combine features with scipy.sparse.hstack to handle high dimensionality efficiently.
- Standardize numeric features to comparable scales.

TF-IDF on artist/label names captures semantic patterns that simple categorical encoding misses.

4. SPARSE MATRICES FOR SCALABILITY

With 395k records and high-dimensional TF-IDF features, use scipy.sparse matrices throughout. Don't convert to dense arrays - this causes memory exhaustion. Most sklearn estimators handle sparse input natively. Process predictions in batches if needed.

5. FOCUS ON THE PRIMARY DRIVER

ML model predictions will drive ~70% of coverage. Propagation strategies (master_id grouping) add ~3-5% supplemental coverage. Don't over-invest in clever propagation at the expense of building a strong baseline model. Start with solid features and calibration, then add propagation if time permits.

6. VALIDATE PROPAGATION ASSUMPTIONS

Records sharing master_id are correlated but not identical. Naive propagation (query 1, apply to all siblings) achieves ~82% accuracy - below the 90% precision requirement. If using master_id grouping, validate with majority voting (query 2-3 per group) or measure actual precision on held-out examples. Be cautious with master_id='0' - it's a sentinel for unrelated records, not a real group.

7. STRATIFIED VALIDATION

Use stratified train/test split to match the 22.82% positive rate in validation. This ensures threshold tuning on validation generalizes to test. Never tune on the test set. With matching distributions (no shift), validation metrics reliably predict test performance.

8. ACTIVE LEARNING AND STRATEGIC API USAGE

With only 1,000 API calls for 395k records, maximize information gain per query. After training on 30k labeled data and making initial predictions on the full catalog:
- Query records near decision boundaries (probability near your thresholds) where the model is most uncertain
- Use API results to validate model predictions in high-uncertainty regions
- Consider querying representative samples from large master_id groups to validate propagation accuracy
- Each API call can inform not just that record, but similar records or siblings in the same group

This is different from random sampling - active learning focuses budget on informative examples that reduce model uncertainty most efficiently.
