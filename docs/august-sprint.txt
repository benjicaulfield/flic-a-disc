WHERE THINGS ACTUALLY STAND (audited 2026-08-21, updated during Day 1 work)

The eBay pipeline is two-stage, not three, per the July 13 redesign: 10,000 raw listings →
logistic-regression classifier scores all 10,000 → sorted by keeper_score → top 1,000 enriched via
eBay API → cached. TF-IDF pre-filter was removed for causing recall failures. The classifier is
real: 54,998 labeled listings, ~813 keepers (1.6% positive rate), ROC AUC 0.892, PR AUC 0.284,
operating threshold 0.3.

But backend/internal/handlers/ebay.go still carries the old three-stage skeleton (log lines
literally say "Stage 1", "Stage 2", "Stage 3"). Stage 3 (~line 595-610) is dead code: it re-sorts
already-scored listings by the Stage 1 score and calls it "final ranking."

Discogs annotation (BySeller) is real and working, including the wantlist integration — correcting
an earlier note in session-summary.txt that called this unbuilt. ml/bandit/views.py:1105
(discogs_annotate) already calls authenticate_client() and discogs_identity.wantlist.add(release) /
.remove(release) — real Discogs API calls, not a stub. Worth verifying end-to-end (Day 8) but the
code exists.

eBay annotation is more built than it looked from the Go side alone. ml/bandit/views.py:507
(ebay_annotate, mounted at POST /ml/ebay/annotated/) already accepts {annotations: [{ebay_id,
label}]} and updates EbayListing.wanted/evaluated. What's actually missing: (1) the Go route + a
thin proxy handler — POST /api/ebay/annotate doesn't exist in main.go — mirroring
DiscogsAnnotateHandler (discogs_byseller.go:63), which is itself just a ~25-line
forward-the-request-body proxy to Django; (2) the frontend UI in EbayTab.tsx — the "Annotate" toggle
button exists and does nothing else, no checkbox column, no submit; (3) ebay_annotate doesn't
trigger any retraining, unlike discogs_annotate which calls trainer.update_model_online(...) when
annotations carry a probability — that's real remaining work (Day 4).

Pricing formula is stale in the file that exists for it. ml/bandit/utils/required_margin.py
(untracked, sitting in the repo) implements the OLD sliding-margin formula that the July 13 session
explicitly replaced for underpricing bids ($45 record → $18.71 max bid, rejected as untenable). The
new formula — fraction = 0.75 - 0.273 * exp(-0.02 * sell_price); bid = sell_price * fraction -
shipping — exists only in the session summary, not in code. Neither version is wired into any API
payload or any of the three tabs yet.

No scheduler exists. Nightly retrain (classifier + TF-IDF-for-Discogs + bandit) is fired by manual
curl, not a cron job or systemd timer.

The droplet was running February code, not anything current, until Day 1's reconciliation fixed it.
deploy.sh does git reset --hard origin/main on the server. Local main and origin/main had diverged
back in Jan/Mar 2026 — traced during Day 1: local main was hard-reset to bb68a7d (Jan 7) at some
point after Mar 25, discarding ~24 commits' worth of shared history, then a single giant commit
(c52f77e, "functioning stopping place," 577 files, +23M lines — mostly the ml/catalog/archive data
dumps) landed June 29 with no further pushes since. origin/main's ebay.go didn't even have the
classifyListings function — everything from the March-onward classifier redesign had never been
deployed.

Day 1 reconciliation: DONE. Full 22-file diff audit confirmed origin had nothing local didn't
already supersede or contain under a renamed path (python_services/ → ml/, handlers.go → split into
todos.go/discogs_knapsack.go/discogs_ranking.go/discogs_annotation.go, interfaces.ts → split into
types/*.ts). Tagged origin's old tip as pre-reconcile-backup (3241468, permanently recoverable).
Force-pushed local over origin. Along the way, the push was rejected for oversized files — the giant
June 29 commit had added ml/bandit/data/lp_catalog.json (983MB!),
ml/catalog/data/signal_records.jsonl (169MB), ml/catalog/data/lp_catalog_enriched.json (141MB), and
a duplicated RAG chroma db (60MB) straight into git. Fixed by resetting to bb68a7d, excluding those
paths via .gitignore (ml/catalog/, ml/bandit/data/lp_catalog.json, archive/ml/rag/), and
recommitting clean (373 files, 230K insertions instead of 23M). Also found and stripped a stray 36MB
compiled Go binary (backend/api) that had been committed by accident — gitignored backend/api and
backend/flic-go going forward. Final push succeeded: origin/main and local main both now at 3e5d524.

deploy.sh builds the wrong binary path on both sides of the divergence — go build -o flic-go
./cmd/server, but the actual entrypoint is backend/cmd/api/main.go. Not a reconciliation risk, just
a real bug that predates the split and needs fixing (Day 20).

UserDashboard.tsx is a Trello-style kanban plus a recharts performance line chart plus a stats
