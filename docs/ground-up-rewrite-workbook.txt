GROUND-UP REWRITE — 30 days, by hand, no exceptions

Scope locked in before Day 1: code is rewritten from zero (models, views, handlers,
components, training/scraping logic — all hand-retyped, not ported). Same stack (Go +
Django ML service + React/Vite + Postgres) — this isn't a technology problem, it's a
detachment problem. No marketplace. Exactly two pages when this is done: landing page
and deck. Everything that used to be its own page (dashboard, the Discogs*Training
pages, the tour) becomes a deck tab, a section, or gets cut outright.

One assumption stated explicitly rather than left silent: "from zero" means the CODE.
The real data underneath it — the Discogs catalog, years of scraped eBay/Discogs
listings, actual labeled training examples, the 199+ seller shipping-policy rows you
hand-researched into sellers_sorted.json — gets preserved and imported once into the
new schema, not regenerated from scratch. Re-collecting years of real market data in
30 days isn't the point of this exercise; owning the code that touches it is. If that's
wrong, say so before Day 2 and this gets cut.

RULES FOR THIS REWRITE

Code is rewritten from zero, by hand. Real historical data — the catalog, labels,
scraped listings, the seller shipping research — is preserved and imported once, not
regenerated. Re-collecting years of real market data in 30 days isn't the point;
owning the code that touches it is.

Two pages, no more. Landing and deck. Anything that used to be its own page becomes a
tab, a section, or gets cut — decided explicitly every time, never carried forward by
default just because it existed before.

No marketplace. Out of scope for this rewrite, full stop.

Log bloat as you hit it. Every dead function, unused page, or pointless abstraction
gets a line in the nearest open day's bloat sweep the moment you notice it — don't
wait for the scheduled sweep days.

Old main is untouched and keeps serving the live site until Day 29. All the risk of
this rewrite lives on the branch; production stays boring until cutover.

One commit per day minimum, legible history.

Protect the checkpoints: Sep 26, Oct 3, Oct 10, Oct 17. If a day slips, carry the
task, protect the checkpoint.

Verify before rebuilding, even in a from-scratch rewrite — read what the old code
actually did before retyping it, especially around the two known landmines already
found once: get_user_inventory's interactive-auth crash on a non-interactive server,
and eBay's now-invalid sort=itemEndDate parameter.
