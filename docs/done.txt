2026-08-21 — Day 1

Reconciled six months of diverged git history. Local main and origin/main
had split back in Jan/Mar 2026 after a hard reset discarded ~24 shared
commits; local had since accumulated a giant June 29 snapshot commit no one
ever pushed. Audited all 22 files both sides touched since the fork —
confirmed origin had nothing local didn't already supersede or contain
under a renamed path. Tagged origin's old tip (pre-reconcile-backup,
permanently recoverable) and force-pushed local over it.

Found and removed ~1.3GB of data dumps that had landed straight in git
history during that giant commit (ml/bandit/data/lp_catalog.json at 983MB,
plus two more catalog/RAG files over GitHub's 100MB hard limit) — the
push was rejected until these were stripped. Also found and removed a
stray 36MB compiled Go binary that had been committed by accident.

Triaged the untracked file pile left over after the above. Found
frontend/src/components/EbayTab.tsx — the shared component Auction and
BuyItNow both import — was never tracked in git at all; a fresh clone
would have failed to build. Committed it along with six real Django
migrations, new management commands, the eBay classifier training
scripts, and the sprint/session docs. Deleted two unrelated files that
had nothing to do with this project (a personal workout list at
sellers.txt, a stray "zines" dataset).

Landed and pushed a large pile of pending feature work that had been
sitting uncommitted in the working tree the whole time — the actual eBay
pipeline redesign and tab updates from the July session, never committed:
main.go, the eBay client and handlers, models.go, the three daily-use
tabs, several ml/bandit files. This was the real bulk of "current
progress" and it had never made it into git history until today.

Ran the first real deploy since February and found (and fixed) five
separate production bugs along the way, none of which deploy.sh alone
would ever have caught:

  - Migration 0041 failed on Postgres: couldn't cast an empty-string
    default to jsonb. Fixed with an explicit RunSQL + USING clause,
    verified in a dry-run transaction against production before applying.
  - Migration 0050 failed the same way, but worse: a price column had
    currency text embedded in it ("20.0, USD"). Fixed, and in the
    process recovered real currency data (USD/EUR/GBP/BRL/SEK) that had
    been sitting unpopulated in its own dedicated column the whole time.
  - Migration 0052 failed on real schema drift — django_migrations
    claimed a column existed that the live table never actually had.
    Fixed with SeparateDatabaseAndState so it's correct regardless of
    which environment's database it runs against.
  - deploy.sh built the Go binary from the wrong path (a bug that
    predated all of this) and printed "Deployment complete" even when
    the remote script failed partway through. Fixed both.
  - The frontend build was broken: an invalid tsconfig option
    (ignoreDeprecations set to a TypeScript version that doesn't exist
    yet), a stray include pointing tsc at dead files under archive/,
    and an orphaned hook file with a real undefined-variable bug that
    had been silently failing every build.
  - The Python venv itself was broken: every installed console script
    (gunicorn included) had its interpreter path hardcoded to the old
    pre-rename python_services/ directory. Rebuilt clean.

End state: origin/main and local main match, the droplet is running
current code for the first time since February, all three services
(flic-go, flic-django, nginx) confirmed active, site returns 200,
API returns 401 as expected when unauthenticated.

Fixed the "red line" tsconfig regression: the editor's own bundled
TypeScript (newer than the 5.8.3 pinned in package.json) was flagging
baseUrl as deprecated and suggesting ignoreDeprecations: "6.0" to
silence it — the same invalid value that broke the real build earlier.
Pointed VS Code at the project's actual TypeScript via
.vscode/settings.json (gitignored/local-only, matching existing
convention) instead of masking the warning with a setting that
breaks CI.

First self-driven deploy (user, not Claude) via the now-fixed
deploy.sh. It worked end to end — but surfaced two more real gaps:

  - EbayListing.keeper_score and .source were defined on the model
    but never migrated at all (migration 0059 didn't exist). Both
    fields are referenced throughout the eBay pipeline code; any
    production query touching them would have thrown column-does-not-
    exist. Turned out both already existed on the live table anyway —
    added manually at some point, never recorded in django_migrations,
    wrong shape (nullable, no defaults, keeper_score as numeric
    instead of double precision). ebay_listings had 0 rows in
    production, so no data to preserve: dropped the ad-hoc columns and
    let a proper AddField migration recreate them correctly. Confirmed
    with makemigrations --dry-run --check afterward: no drift left.
  - backend/flic-go (the compiled Go binary) was still tracked in git
    despite being added to .gitignore earlier — gitignore doesn't
    untrack already-tracked files. deploy.sh's git add was re-
    committing a binary diff on every deploy. Untracked it properly
    (git rm --cached); rebuilt the binary on the droplet since
    untracking + git reset --hard deleted the on-disk file (the
    already-running process kept serving from its deleted-but-open
    file handle in the meantime, so no actual downtime).

Open item, not yet resolved: a self-driven commit ("catching up")
added backend/csvs/ — 38 files, ~276K lines of eBay scrape CSVs — under
a path .gitignore doesn't cover (it only matches backend/ebay_*.csv
directly, not the new backend/csvs/ subdirectory). Not near GitHub's
size limits, but it's the same category of noise removed on Day 1.
Decision pending: add a gitignore rule and strip from history, or
leave it.


2026-08-24/25 — Day 3

Extracted BySeller's inline renderAnnotationCell closure into a real,
generic AnnotationCell component (dbValue/dbEvaluated/override/onToggle
as props, no knowledge of row shape or field names) — first piece of
generalizing the shared design across the eBay tabs and BySeller.
Deleted features/deck/columns.ts along the way: an orphaned, unused
file duplicating joinList/money and defining eBay column sets that
didn't even match what EbayTab actually renders.

Built out Day 3 fully: annotation state keyed by ebay_id, a checkbox
column (via AnnotationCell) shown while annotating, a Submit button,
and a submitAnnotations function matching Django's ebay_annotate
payload shape exactly, on EbayTab.tsx (shared by Auction and BuyItNow).
Found and fixed a real bug blocking it: the Go proxy posted to
/ml/ebay/annotate/, but Django only serves /ml/ebay/annotated/ (extra
"d") — every submission would have 404'd.

Found and fixed a second real bug while working in the same area: the
Go EbayListing struct still had Genre/Style as plain strings with
json:"genre"/"style", never updated after migration 0052 renamed the
underlying columns to genres/styles (plural). The frontend's
baseEbayColumns has been reading genres/styles the whole time — the
Genre/Style columns on Auction and BuyItNow have likely been rendering
blank since that migration landed. Renamed to Genres/Styles as
StringSlice/jsonb, mirroring the Format field's existing pattern.
Verified production's genres/styles/format are already jsonb — no
schema change needed, this only fixed what Go sends.

Deploying the above surfaced one more gap: BySeller.tsx imported a
type (Annotation) from types/common.ts that only existed in a local,
uncommitted edit — passed local tsc -b clean (since the local file had
it) but broke the droplet's build (TS2305) since the export had never
actually been committed. Added the missing export (a small, clearly-
needed addition, not scope creep into unrelated in-progress work) and
redeployed clean.

End state: origin/main and droplet both at 5adcd4d, all three services
active, frontend and Go builds both clean, site 200, API 401 as
expected.
